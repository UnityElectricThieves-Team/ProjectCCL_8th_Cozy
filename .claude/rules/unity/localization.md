# 다중 언어(로컬라이제이션) 규약

화면에 보이는 글자를 여러 언어로 내보내기 위한 규칙입니다. 아직 구현 전이라, 여기 적힌 것은 구현할 때 지킬 방향입니다.

## 지원 언어는 다섯 개이고, 언어 태그로 저장합니다

출시 때 지원할 언어는 한국어, 영어, 일본어, 중국어 간체, 중국어 번체입니다.

설정 파일에는 언어를 **BCP 47 언어 태그** 문자열로 저장합니다. IETF(인터넷 표준을 정하는 단체)가 정한 표준으로, 브라우저와 .NET의 `CultureInfo`가 쓰는 표기와 같습니다.

| 언어 | 태그 |
|---|---|
| 한국어 | `ko-KR` |
| 영어 | `en-US` |
| 일본어 | `ja-JP` |
| 중국어 간체 | `zh-Hans` |
| 중국어 번체 | `zh-Hant` |

중국어는 지역(`zh-CN`, `zh-TW`)이 아니라 문자 체계(`Hans` = 간체, `Hant` = 번체)로 나눕니다. 우리가 가르려는 것은 어느 나라인지가 아니라 어느 글자를 쓰는지이기 때문입니다.

enum 순서 번호를 그대로 저장하지 않는 이유가 있습니다. 순서 번호로 저장하면 언어를 목록 중간에 끼워 넣거나 드롭다운 순서를 바꾸는 순간, 기존 저장 파일이 다른 언어를 가리키게 됩니다. 태그로 저장하면 순서가 어떻게 바뀌어도 안전합니다.

태그 목록은 코드의 `LanguageCodes` 한 곳에만 둡니다. **그 목록의 순서가 곧 설정 패널 언어 드롭다운의 옵션 순서입니다.** 드롭다운 옵션은 프리팹에 있어 코드와 따로 움직이므로, 언어를 추가하거나 순서를 바꿀 때는 둘을 함께 고칩니다. 순서가 어긋나도 저장 파일은 깨지지 않지만, 드롭다운에서 고른 언어와 실제로 적용되는 언어가 달라집니다.

## 번역 원본은 Figma이고, 게임에 들어가는 JSON은 사본입니다

기획자가 Figma에 언어별 UI 사본을 만들어 번역문을 표시합니다. 개발자가 이를 JSON으로 옮겨 Unity에 넣습니다. **Figma와 JSON이 어긋나면 Figma가 이깁니다.** 문구를 바꿀 일이 있으면 JSON을 먼저 고치지 말고 기획에 확인합니다.

Unity Localization 패키지는 쓰지 않고 직접 만든 가벼운 표를 씁니다. 그 패키지는 Addressables에 의존해 상주 메모리와 빌드 구조가 무거워집니다. 이 게임은 리소스 점유를 최우선으로 두고, 문장 수도 수백 개 수준이라 패키지의 도구가 그 비용만큼 값을 하지 않습니다.

## 화면 글자는 키로 찾아 씁니다

- **프리팹·씬·코드에 표시용 문장을 직접 넣지 않습니다.** 텍스트는 키(stringID)를 들고 있고, 실제 문장은 현재 언어의 표에서 가져옵니다.
- **프리팹에 고정된 문구는 `LocalizedText`를 붙이고, 코드가 채우는 문구는 그 코드가 `LocalizationManager`에서 직접 가져옵니다.** 둘을 한 텍스트에 같이 쓰면 언어가 바뀔 때 서로 덮어씁니다.
- **stringID는 `화면.구역.항목` 모양으로 점으로 나눕니다.** 첫 칸은 어느 화면인지를 PascalCase로 적고(`UISettings`, `UIShop`, `UIInventory`, `UICollection`, `UITutorial`), 나머지 칸은 소문자와 밑줄로 씁니다(예: `UISettings.row.always_on_top`). ID만 보고도 문구가 화면 어디에 있는지 알 수 있게 하려는 것입니다.
- **문장을 조각내 이어 붙이지 않습니다.** 언어마다 어순이 달라 조각 단위로는 번역할 수 없습니다. 숫자·이름처럼 실행 중에 채워지는 부분이 있으면 문장 전체를 키 하나로 두고, 그 자리를 이름 붙인 변수로 비워 둡니다.
- **변수 이름은 영어 대문자와 밑줄로 씁니다** (예: `{AGE}`, `{ITEM_COUNT}`). `{0}` 같은 번호보다 번역하는 사람이 무엇이 들어갈지 알기 쉽습니다.
- 날짜·숫자 표기도 언어마다 다르므로, 한국어 형식(`M월 d일` 등)을 코드에 고정하지 않습니다.
- **코드는 `LocalizationManager.Localize`로 문장을 가져오고, `LanguageChanged`를 구독해 다시 그립니다.** 드롭다운 옵션처럼 `LocalizedText`를 붙일 수 없는 글자도 이 방식으로 채웁니다.
- **언어 드롭다운의 언어 이름은 번역하지 않습니다.** 각 언어를 자기 말로 적습니다(English, 한국어, 简体中文, 繁體中文, 日本語). 지금 언어를 읽지 못하는 사람도 자기 언어를 찾을 수 있어야 하기 때문입니다.

## `LocalizedText`는 가능한 한 공통 프리팹에 한 번 붙입니다

패널 제목은 `UIPanel_Base`에, 설정 행 이름은 `SettingsRow`에 붙어 있습니다. 공통 프리팹의 컴포넌트는 **ID를 비워 두고**, 실제 ID는 각 배리언트나 행 인스턴스에서 덮어씁니다. 제목 글자를 이미 배리언트마다 덮어쓰고 있으니 ID도 같은 자리에서 덮어쓰는 것입니다. 이렇게 두면 새 패널이나 새 행을 만들 때 컴포넌트를 빠뜨릴 수 없고, ID를 안 넣으면 `[~]`로 보여 바로 드러납니다.

- **배리언트에 붙인 컴포넌트를 "Apply to Base"로 올리지 않습니다.** ID까지 베이스로 올라가, 덮어쓰지 않은 모든 패널에 같은 문구가 뜹니다. 공통 프리팹에서 빈 ID로 새로 붙입니다.
- `LocalizedText`는 한 오브젝트에 하나만 붙습니다. 공통 프리팹으로 옮길 때는 배리언트 쪽 컴포넌트를 먼저 지웁니다.
- 탭이나 버튼처럼 패널마다 따로 있는 오브젝트는 그 패널 프리팹에 직접 붙입니다.

## 번역 대상과 비대상

**대상**: 프리팹·씬의 UI 문구, 코드가 조립하는 문구, 상점 상품명, 캐릭터 이름, 도감 프로필(이름·취미·회상 문구 등).

**비대상**: `Debug.Log` 메시지, 인스펙터 `[Tooltip]`·`[Header]`, 코드 주석. 개발자만 보는 글이라 번역하지 않습니다.

캐릭터 이름과 도감 프로필도 번역 대상이라는 것을 놓치지 마세요. 지금 이들은 필드 하나에 한 언어 문장만 담는 구조라, 표에 키를 넣는 것만으로는 해결되지 않고 데이터 구조부터 바꿔야 합니다. 도감 데이터를 만드는 WPF 툴은 저장·도감용 도구라 언어 시스템과 엮지 않기로 했습니다. 도감 프로필을 어떻게 번역할지는 아직 정하지 않았습니다.

## 번역 표는 한 번 읽어 전부 들고 있습니다

표는 `Assets/Localization/Strings.json` 하나이고, `stringID → { 언어 태그 → 문장 }` 모양입니다. 시작할 때 한 번 읽고 다섯 언어를 전부 들고 있습니다. 빈 칸을 다른 언어로 채우려면 어차피 여러 언어를 함께 들고 있어야 하고, 문장 수백 개 규모에서는 수십 KB라 부담이 없기 때문입니다. 문장이 수천 개로 늘어 언어당 수 MB가 되면, 그때는 언어별 파일로 나눠 바꿀 때마다 읽는 방식으로 옮깁니다.

## 빈 칸은 en-US, 그것도 비면 가짜 번역으로 채웁니다

현재 언어 칸이 비어 있으면 en-US 문장을 보여줍니다. en-US도 비어 있으면 **가짜 번역**을 보여줍니다. 한국어 문장을 괄호로 감싸고 약 40% 늘린 것입니다(예: `[설정~~]`). 한국어도 비어 있으면 stringID를 같은 모양으로 보여줍니다.

가짜 번역이 화면에 보이면 그 문장은 번역이 빠졌다는 뜻입니다. 무슨 문구인지는 읽을 수 있으면서 빠진 곳이 눈에 띄고, 늘어난 길이 때문에 긴 언어가 들어왔을 때 넘칠 UI도 함께 드러납니다. **그래서 출시 전에는 en-US 칸이 하나도 비어 있으면 안 됩니다.**

## 언어가 바뀌면 이벤트로 다시 그립니다

`LocalizationManager`는 `SettingsManager.Changed`를 구독하되, 언어가 실제로 바뀐 때만 자기 `LanguageChanged`를 울립니다. `Changed`는 토글 하나만 바뀌어도 울리기 때문입니다. 텍스트는 `LanguageChanged`를 구독해 스스로 글자를 다시 채우고, 언어를 바꾼 쪽이 화면의 텍스트를 찾아다니며 갱신하지 않습니다. 구독한 컴포넌트는 파괴될 때 반드시 구독을 해제합니다.

## 아직 지원하지 않는 언어

한국어와 영어 외의 세 언어는 번역이 준비될 때까지, 설정에서 고르면 **"아직 지원하지 않는 언어입니다"** 안내를 띄웁니다. 안내를 어디에 어떻게 띄울지, 선택 자체를 되돌릴지는 UI 쪽과 함께 정해야 해서 아직 정하지 않았습니다.

## 폰트

언어별 폰트와 크기는 기획자가 정해서 알려주기로 했습니다. 정해지기 전에는 임의로 폰트를 추가하거나 대체 폰트(fallback)를 연결하지 않습니다.

지금 폰트는 모두 한국어용이라 일본어·중국어 글자가 빠져 있습니다. 대체 폰트 없이 언어만 바꾸면 글자가 네모(□)로 나옵니다.

## 나중에 하면 좋을 것

- 중국어·일본어 폰트를 넣었을 때 메모리가 얼마나 늘어나는지 측정합니다. TMP 폰트가 Dynamic 모드라 글자 종류가 많은 언어일수록 아틀라스가 커집니다. 필수는 아니고, 폰트가 정해진 뒤 여유가 있을 때 합니다.
