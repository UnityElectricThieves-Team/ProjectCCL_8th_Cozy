# 배경 규약

뷰포트 아래에 깔리는 배경에 대한 규칙입니다. 구체 수치는 프리팹에서 확인하세요 — 여기에는 바뀌지 않는 것만 적습니다. 캐릭터가 밟는 지면 자체는 [character-ground.md](character-ground.md)를 봅니다.

## 배경은 아트가 만든 프리팹 하나입니다

배경 상품 하나는 아트가 만든 배경 프리팹 하나입니다(`Resources/Backgrounds/<이름>/background.prefab`). 한 배경이 그림 여러 층(하늘·방 등)과 파티클(별똥별 등)을 함께 담을 수 있어야 해서, 그림 한 장을 받는 방식을 버렸습니다.

**프리팹은 아트 작업물을 거의 그대로 씁니다.** 개발 쪽에서 크기를 바꾸거나 타일 개수를 다시 맞추지 않습니다. 배경 높이의 표준은 마스터 캔버스 기준 500px(베이스 공간 px — 정의는 [viewport-coordinates.md](viewport-coordinates.md))이지만, 배경마다 조금씩 달라도 됩니다. 크기나 비율이 이상하면 코드로 메우지 않고 아트에 수정을 요청합니다.

- 상품은 배경 프리팹을 직접 참조합니다. `Resources/`에 있는 것은 아트가 처음 넣은 자리일 뿐이고, 경로 문자열로 읽지 않습니다. 장식과 같은 이유입니다([decoration-placement.md](decoration-placement.md)).
- 상점 썸네일(`icon`)은 배경 프리팹과 따로 둡니다. 썸네일은 상점 카드 비율에 맞춘 작은 그림이라 배경 원본으로 대신할 수 없습니다.

## 배경은 뷰포트 아래 변에 붙습니다

프리팹 안 그림 전체(스프라이트들을 합친 범위)의 아래 끝을 뷰포트 아래 변에, 가로 가운데를 뷰포트 가운데에 맞춥니다. 지면이 뷰포트 아래 변 하나뿐이라는 규약과 같은 자리를 가리켜서, 캐릭터가 배경의 바닥선 위에 서 있는 것처럼 보입니다. 파티클은 이 범위에 넣지 않습니다. 떠다니는 것이라 바닥의 기준이 될 수 없기 때문입니다.

기준이 프리팹 원점이 아니라 그림인 이유는, 아트 프리팹마다 원점이 그림의 어디에 있는지가 제각각이기 때문입니다. 장식이 그림의 아래 끝으로 지면을 맞추는 것과 같은 판단입니다.

**편집 중 핸들을 끄는 동안에도 프리뷰를 따라갑니다**(마스크 포함). 기획이 "뷰포트를 옮기는 즉시 배경도 같이 이동"을 요청했고(2026-11-14 수정요청 시트), 저장했을 때의 배경을 끄는 동안 미리 보여 줍니다. 예전에는 "끄는 동안 배경까지 움직이면 조작이 어렵다"며 따라가지 않았는데, 배경에 대해서는 이 판단을 버렸습니다. 캐릭터·구름이 끄는 동안 따라가지 않는 이유는 [viewport-coordinates.md](viewport-coordinates.md)의 "뷰포트 밖에 남은 것" 절에 있습니다.

## 뷰포트 밖은 마스크로 자릅니다

아트 프리팹은 타일 개수가 고정이라 뷰포트보다 넓게 뻗어 있습니다. 창은 작업 영역 전체를 덮고 있어서, 그대로 두면 뷰포트 밖 바탕화면 위에도 배경이 그려집니다. 그래서 뷰포트 크기의 SpriteMask(그 영역 안만 보이게 하는 마스크)를 하나 두고, 배경 프리팹의 렌더러(파티클 포함)가 그 안에서만 보이게 합니다.

마스크가 자르는 정렬 범위는 그 배경 프리팹 렌더러들의 Order in Layer 최솟값~최댓값으로 좁힙니다. 범위를 두지 않으면 씬의 다른 "마스크 안에서만 보이기" 렌더러까지 이 마스크를 타기 때문입니다. 범위는 프리팹마다 렌더러에서 읽으므로, 아트가 Order 값을 바꿔도 코드를 고치지 않습니다. 대신 배경이 아닌 것이 배경의 Order 범위 안에 들어가면 함께 잘릴 수 있으니, 아래 정렬 규칙을 지킵니다.

반대로 뷰포트가 프리팹보다 넓으면 양 끝이 비어 바탕화면이 비칩니다. 이 경우도 코드로 타일을 늘리지 않고 아트에 더 넓게 만들어 달라고 요청합니다.

## 배경에는 콜라이더를 붙이지 않습니다

`WindowManager`가 매 프레임 커서 아래에 콜라이더가 있는지로 클릭 통과를 끕니다. 레이어를 가리지 않습니다. 배경에 콜라이더가 있으면 배경 전체에서 바탕화면 클릭이 막혀, 그 아래 있는 바탕화면 아이콘을 누를 수 없게 됩니다. 아트 프리팹에 콜라이더가 들어 오면 빼 달라고 요청합니다.

배경 위 클릭을 막는 것이 기획 의도가 되면, 그때는 이 규칙을 바꾸는 것이 아니라 `WindowManager`의 판정 방식과 함께 다시 정합니다.

## 배경을 까는 쪽은 상점을 모릅니다

상태의 주인은 `BackgroundSystem`, 활성 배경의 프리팹을 넘기는 것은 Contents의 바인더, 화면에 까는 것은 Gameplay의 `BackgroundStage`입니다. 장식과 같은 3단 구조입니다. 활성 배경이 없으면 아무것도 깔지 않아 바탕화면이 비칩니다.

배경이 바뀔 때만 프리팹을 새로 만들고 이전 것을 지웁니다. 드물게 일어나는 일이라 풀링하지 않습니다.

## 정렬은 Default 레이어의 음수 Order in Layer로 합니다

새 Sorting Layer를 만들지 않습니다. ProjectSettings를 건드리지 않기 위해서입니다. 배경 프리팹 안의 층끼리 앞뒤는 아트가 넣은 값을 그대로 쓰고, 덮어쓰지 않습니다. 캐릭터·구름·달·장식은 모두 배경보다 큰 Order in Layer를 가져야 합니다. 값은 프리팹에서 확인합니다.
