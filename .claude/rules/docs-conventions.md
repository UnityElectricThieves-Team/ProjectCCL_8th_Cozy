# 문서 작성 컨벤션

## 파일/폴더 명명

`Docs/` 아래의 문서와 폴더에 적용합니다. 본문은 한국어로 쓰고, 파일명만 영문입니다.

- **영문 PascalCase, 구분자 없음.** `_`, `-`, 공백을 쓰지 않습니다. 예: `GameConceptDirection.md`, `AnimationList.md`.
- **약어도 붙여서 씁니다.** `AILogic.md`, `UIMenuBarDesign.md`, `WsExTransparentMouseInputStudy.md`.
- **날짜는 파일명에 넣지 않습니다.** 작성일은 본문 첫 줄에 적습니다. 파일명에 날짜를 붙이면 정렬은 되지만 내용을 찾기 어려워집니다.
- 한글 파일명은 쓰지 않습니다 (git이 경로를 escape 표기하고, 링크에 `%20`이 섞입니다).

`.claude/rules/`의 소문자 kebab-case 파일명(`docs-conventions.md`, `ui-panels.md` 등)은 **이 규칙의 대상이 아닙니다.** Claude Code 쪽 관례를 따릅니다.

## 문서 영역

- `Docs/Development/` — 개발. 저장소에서 실제로 쓰고 고치는 문서는 여기 있다.
- `Docs/Planning/` — 기획 사본. **기획은 Figma와 Notion에서 작업하므로 여기에 새 기획 문서를 만들지 않는다.** 이미 있는 것은 개발자가 1차로 해석해 옮겨둔 사본이고, 원본과 어긋나면 Figma·Notion이 이긴다.
- `Docs/Art/` — 아트.

새 문서는 자신의 영역 폴더 안에 배치한다.

## 각 층에 무엇을 적는지

어느 층이 무엇을 담는지는 **루트 [CLAUDE.md](../../CLAUDE.md) §4가 정본**이다. 여기서는 글을 쓸 때의 규칙만 다룬다.

### 서브 디렉토리 CLAUDE.md
- 파일을 하나하나 나열하지 않는다. 목록은 폴더를 보면 되고, 문서에서 얻어야 하는 건 **어디서부터 읽어야 하는가**와 **쓰면 안 되는 것이 무엇인가**다.
- 한 디렉토리당 한 화면을 넘기지 않는 것이 이상적.

### .claude/rules/
- **왜 이렇게 하는지**를 함께 적는다. 이유 없는 금지문은 지켜지지 않고, 상황이 바뀌었을 때 폐기해도 되는지 판단할 수 없다.
- **줄번호와 직렬화 값을 적지 않는다.** `Foo.cs:42`나 프리팹의 `preferredHeight: 160` 같은 값은 코드가 조금만 바뀌어도 낡는다. 변하지 않는 불변식으로 쓰고, 구체 수치는 "코드/프리팹에서 확인"으로 넘긴다. 줄번호를 박아도 되는 곳은 특정 시점의 스냅샷인 `Docs/Development/`의 조사·이관 문서다.
- 규칙을 쓰기 전에 **그 규칙을 어길 수 있는 파일이 자기 `paths`에 걸리는지** 확인한다. 안 걸리면 발화하지 않는 규칙이 된다 (루트 §4의 함정 참고).

## 단일 진실 원천

- 동일 정보를 여러 문서에 중복 적지 않는다. 같은 내용을 두 곳에 적으면 반드시 갈라진다.
- 중복이 생길 것 같으면 한쪽을 정본으로 정하고 다른 쪽은 링크만 둔다.

## 업데이트 의무

폴더 구조나 코드가 바뀌면 관련 CLAUDE.md / rules 파일을 함께 업데이트한다. **outdated된 문서는 잘못된 정보보다 위험하다.** 그래서 애초에 낡기 쉬운 정보(줄번호, 수치, 진행 상황)를 오래 사는 층에 적지 않는 것이 중요하다.
